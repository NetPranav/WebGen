### Phase 13 / 24 / 25 groundwork (v3 Sub-Phase 43.2, Tool State Machine): specified in full, Tier A's non-editing shapes built

*Work done 2026-09-27 under v3 numbering (v3 43.2 → v4 Phases 24 and 25; the menu/command-bus work → v4 Phase 13). The full 43.2 spec is in `ROADMAP_v3_ARCHIVE.md`, Phase 43.*

At the user's request, 43.2's tool list was rethought from scratch — expanded well beyond the original plain drawing-tool set to cover what a complex-animation author needs (Motion Path, Gradient, Anchor Point) that a static design tool doesn't, with an explicit "considered and excluded, here's why" section for masking, boolean ops, puppet warp, and a 3D camera tool. Every claim about existing codebase capability was independently verified before being written down. Full spec in ROADMAP.md's Phase 43.2 section; then, at the user's explicit choice, Tier A's shape/creation tools were actually built — Select, Hand, Frame, Rectangle, Ellipse, Line, Text — real and tested, not stubs.

#### Added
- **`src/editor/canvas/tools/`**: `types.ts` (`ShapeToolDefinition`), `shapeTools.ts` (`SHAPE_TOOLS` registry, pure `computeShapeProperties` sizing logic — one shared implementation for Frame/Rectangle/Ellipse/Line rather than four near-duplicate handlers), `useShapeDrawing.ts` (the drag-mechanics hook). 5 new unit tests.
- `FloatingDock.tsx`'s `CanvasTool` union replaced (`select | pan | pencil | text | wire | shapes | components | assets` → `select | pan | frame | rectangle | ellipse | line | text`) — `wire`/`shapes` retire, `components`/`assets` become Quick-Insert-only. One deliberate breaking key reassignment: `P` moves from Pencil to Pen (not yet built) to match universal design-tool convention.
- `SandboxHost.tsx`: rendering for all 7 of Phase 7.6's shape/vector archetypes (rectangle, ellipse, line, polygon, star, arrow, svgPath) — previously **zero**, all fell through to an invisible default `<div>`. Covered by a new `SandboxHost.test.ts` case.

#### Fixed (all found only by actually building and browser-testing this — none anticipated by the spec)
- `SandboxHost.tsx` had no rendering at all for the shape archetypes 7.6 shipped — a drawn shape would have created correct document data and displayed as nothing.
- A genuine double-creation bug: every drawn shape was created twice. `useShapeDrawing.ts` called the real side effect (`documentCommands.addLayer`) from inside a `setState` updater function — React Strict Mode's dev-mode double-invoke of updaters caught it deterministically ("0→2" every time). Fixed by moving the side effect out of the updater into a plain read at mouseup time.
- The sandbox `<iframe>` (a separate browsing context) silently swallowed every drag that started on top of the rendered device frame, with zero console errors — mouse events over an iframe never reach the parent page. Fixed by disabling the sandbox's `pointer-events` while a shape/text tool is active, so the drag reaches the canvas instead; Select/Hand leave it untouched, since Select's click-to-pick-an-element needs real clicks inside the iframe.
- A second review pass found three more, all from `handleMouseDown`'s new shape/text routing returning early without considering anything else that `mousedown` could mean: `FloatingDock`/`ZoomControls` buttons are children of the same div, so clicking them while a shape/text tool was active created a stray shape/text layer; Space-drag and middle-click-drag no longer panned while a shape/text tool was active (silently regressing 43.3's "Space works everywhere" behavior); the sandbox's `pointer-events: none` toggle didn't exclude Play mode, which would have frozen a running app if a shape tool was still selected when Play was pressed (not verified live — this build has no reachable way to enter Play mode at all; correct by code reading only). All three fixed with one shared `toolCapturesPointer` predicate and a chrome-target check, and re-verified live.

Two earlier, non-isolated runs had failed — once `ProjectSession.test.ts`'s save-status race, once `WasmCableCanvas.test.ts`'s 120fps frame-budget assertion — both while a dev server and Playwright were also running concurrently for manual browser testing. Neither file was touched this session; this is load-dependent flakiness in genuine wall-clock timing/perf-budget tests, not a difference from what's already on `origin/main`. Flagged for whoever next hardens those two tests (a mocked clock, or a more generous budget), not attempted here.
- `onCreated`'s `selectEntity` correctly selects a newly-drawn shape in the modern selection store, but the on-canvas selection outline (`CanvasOverlay.tsx`) only ever highlights the three hardcoded showcase-demo components (an older, separate `selectedElement` mechanism) — a drawn shape is selected but shows no visual highlight box. Cosmetic, pre-dates this phase's selection story, not fixed here.
